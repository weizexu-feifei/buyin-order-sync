# 当前限制与失败处理

1. **新公开版需独立验收。** 离线测试和模拟飞书通过，不等于已在新机构完成真实端到端验证。浏览器选择器依赖页面，登录入口变化可能失败；请保留人工导出/导入路径。
2. **有范围才有结论。** 采集失败、没有新文件、账号无返回均不能写成0。解析行数与声明行数一致只能排除截断，不能证明平台返回没有延迟。人工导入时间、范围和快照时间由使用者如实提供。
3. **历史退款要持续覆盖。** 默认本月且最多回看30天。月初需自行延长范围或执行历史月核对；范围外退款不会被神奇地刷新。工具不自动补历史、不自动删数据。
4. **整单退款，固定计佣口径。** 不适用于部分退款、消费者现金实付、财务净收入或利润。未知状态/负佣金停止，由使用者确认数据含义。
5. **分页保护。** 当前逐付款日读取飞书，NDJSON单日最多2000条；has_more不为false时停止。尚未实现多页拼接，不能跳过检查后继续写。空同步键或重复键同样停止。
6. **专用表。** 当前同步不删除远端多余行；`check`会报告查询日期内多余记录。不要混入人工行、其他任务或同ID不同含义的数据。账号映射修改会更新对应展示字段，但不会清除已移除账号的历史。
7. **范围内完整快照。** 新导入不会因文件缺少某笔订单而自动删除缓存；发生Excel/缓存差异时停止。禁止拿半日文件覆盖已有更完整的同日数据，较旧快照也不能回退订单状态。修复前先备份并核查原因，本版不提供自动清库按钮。
8. **待确认新增。** 接口超时不能说明未写成功。先读回确认，无法确认则留下pending并停止。下次仍缺记录时也不盲目重发；由用户核对飞书及本地批次。不要直接删除SQLite来绕过保护。
9. **定时依赖Windows。** 用户需登录、机器开机、网络可用；Chrome专用资料不能同时被多个进程占用。Catch-up任务可能晚于计划时间运行。程序只读检查任务是否与配置一致，发现漂移不会自动修复。
10. **本地隐私。** 配置、报表、日志、SQLite和浏览器资料必须私有。`.gitignore`不防止手工强制上传或历史泄露。凭据处理依赖用户本机和官方CLI，不提供多人共享登录方案。

退出码0表示该命令完成；1表示停止或失败。`preview`退出0只说明该文件成功解析，不表示已经同步飞书。`written_rows=0`且读回通过/全部跳过才是无变化；同步中失败时实际写入数可能为null，表示尚不确定。订单内部读回与独立三方`check`是两个不同验证层次。

同一平台报表最多两次下载，导出请求约310秒冷却、两小时内优先恢复原报表；父进程限制内部worker等待。出现验证码、403、429、新登录要求或结果未知就停止，不自动绕过、不提高频率。日志中source_as_of_basis说明时间依据，不能把export_requested_at宣称为平台精确生成时刻。
