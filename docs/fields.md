# 飞书字段与原始Excel

目标是专用的平面汇总表，无账号主表、人员关联、AI字段或看板依赖。`schemas/order-fields.json` 为完整建表字段数组，第一列「同步键」为文本主字段；其他字段名与类型必须一致。现有表的公式/关联字段不能直接替代本清单中的普通字段。

| 字段 | 类型 | 含义 |
|---|---|---|
| 同步键 | 文本，主字段 | 付款日期\|精确账号ID\|商品ID，作为防重复标识 |
| 出单日期 | 日期 | 原订单付款日，北京时间 |
| 账号ID、账号名称、所属团队、运营人员 | 文本 | 用户私有配置的映射，名称可变，ID必须稳定 |
| 商品编号、商品标题 | 文本 | 原商品ID及标题，不用短名合并不同商品 |
| 成交金额、支付金额 | 金额 | 原报表成交金额合计，退款前计佣基数 |
| 平台补贴 | 金额 | 原补贴合计，仅留底，不二次扣除 |
| 百应原退款金额、退款金额 | 金额 | 整单退款订单对应的原成交基数合计 |
| 退款平台补贴 | 金额 | 已整单退款订单的补贴合计，仅留底 |
| 实际营业额 | 金额 | 支付金额−退款金额，退款后计佣成交额 |
| 预估佣金 | 金额 | 报表总佣金收入原值合计 |
| 成交订单数、退款订单数、实际订单数 | 整数 | 订单ID计数，实际=成交−整单退款 |
| 成交件数 | 整数 | 商品数量原值合计，未扣除退款件数 |
| 数据截至 | 日期时间 | 快照时间；不是写入飞书时间 |
| 数据来源文件、金额口径 | 文本 | 私有源文件名和当前核算版本 |

只有来源文件名/取数时间改变、业务值完全相同时，跳过远端写入，所以「数据截至」可能保留上一次业务变化的时间。当前全表有效取数时间请看本机last-success。不能把某条汇总的旧时间解读成最近没有采集。

## Excel要求

恰好一个工作表，首行包含：订单id、商品id、商品名称、订单状态、达人昵称、达人抖音号、成交金额、平台补贴、商品数量、订单支付时间、总佣金收入。可有其他列，但每个必需字段恰好出现一次。

订单id和商品id必须为文本，账号ID按文本精确匹配；不从昵称推测ID。选中账号的金额及补贴必须是非负、最多2位小数；缺失、负数、NaN和无穷值均停止。总佣金收入同样要求非负有效金额，负佣金报表暂不支持，不能擅自改成0。

支持订单付款、订单收货、订单结算、订单退货退款。最后一种表示整单退款，按原基数全部冲回。无法从单纯「现金退款150+补贴50」推断部分退款；新状态或部分退款需要另行扩展并提供虚构测试。本工具不读取消费者姓名、电话和收货地址，也不会向飞书发送这些字段；原始导出文件本身仍可能包含敏感信息，必须留在私有目录。
